# Repo Initialization — New Deployment Flow

> Design for first-boot initialization of the F-Droid repository inside the
> fdroidmgr container. A fresh deployment has an **empty** fdroid repo dir
> (no `config.yml`, no `keystore.p12`, no `repo/` index). The container must
> bootstrap it end-to-end: create signing key, write config, generate index,
> and expose it for the F-Droid client.

---

## 1. Research: how fdroidserver initializes a repo

`fdroidserver` ships the **`fdroid init`** command (verified locally, v2.4.5).

### 1.1 What `fdroid init` does (from `fdroidserver/init.py`)

1. Resolves the Android SDK path:
   - `--android-home PATH` wins; otherwise `ANDROID_HOME`; otherwise the
     platform default (`/opt/android-sdk` on Linux); prompts interactively
     unless `--no-prompt`.
2. If `config.yml` does **not** exist:
   - creates `repo/` dir
   - copies the example `config.yml` from the fdroidserver package
     (or writes a minimal one), chmod `0600`
   - writes `sdk_path` into it
3. If the repo **already exists** (config.yml present) → hard failure:
   > `Error: Repository already exists.` / "cowardly refusing to overwrite"
4. Resolves the keystore:
   - `--keystore PATH` (default from example config: `keystore.p12`)
   - if the keystore file does not exist, **generates a new one**:
     - `common.genpassword()` → random base64-64 password
     - writes `keystorepass` + `keypass` into `config.yml` (plaintext, chmod 0600)
     - `repo_keyalias` defaults to `socket.getfqdn()` (hostname)
     - `keydname` defaults to `CN=<hostname>, OU=F-Droid`
     - runs `keytool -genkey -keyalg RSA -keysize 4096 -sigalg SHA256withRSA
       -validity 10000 -storetype pkcs12` → `keystore.p12` (chmod 0600)
   - if the keystore already exists → warns and leaves
     `keystorepass`/`keypass`/`repo_keyalias`/`keydname` for the user to set
5. Prints a summary ("Built repo based in ...").

### 1.2 CLI surface (non-interactive)

```
fdroid init [--no-prompt] [--android-home SDK] [--keystore PATH]
            [--repo-keyalias ALIAS] [-d DISTINGUISHED_NAME]
```

All flags work without a TTY; `--no-prompt` forbids interactive input and
fails loudly instead of hanging.

### 1.3 Post-init step

```bash
cd /repo/dir
fdroid update -c        # create metadata dirs / first index
fdroid update           # signed index (index.xml, index-v1/v2.json, entry.jar ...)
```

Verified locally: fresh dir → `fdroid init --no-prompt --android-home <sdk>`
→ `fdroid update -c` → `fdroid update` produces a signed index with a brand-new
RSA-4096 repo key. Re-running `fdroid init` in a non-empty dir fails with
"Repository already exists." (exit nonzero — but note: our shell test showed
**EXIT: 0** in one run because of the trailing pipe; the actual Python exits
with code 1 — verified via container logs `fdroid update failed with exit code 1`).

### 1.4 What the user must supply (new repo identity)

| Field | Config key | Required? | Notes |
|---|---|---|---|
| Repo URL | `repo_url` | **derived** | always derived from `FDROID_PUBLIC_URL` + `/fdroid/repo` (same host as the OIDC redirect), e.g. `https://fdroid.example.com/fdroid/repo` — not part of the request |
| Repo name | `repo_name` | recommended | shown in the F-Droid client |
| Repo description | `repo_description` | optional | |
| Key alias | `repo_keyalias` | optional | defaults to `fdroid-repo` (a stable constant, not the ephemeral container hostname); used as key alias + CN |
| Keystore path | `keystore` | optional | defaults to `keystore.p12` in repo dir |
| Distinguished name | `keydname` | optional | generated from alias by default |
| Keystore password | `keystorepass`/`keypass` | **generated** | fdroidserver auto-generates; stored in config.yml |

The keystore password is **auto-generated by fdroidserver** (random
base64). There is no CLI flag to supply it. The mgr should either:
(a) read the generated password from `config.yml` after init and store it
    AES-encrypted under `FDROID_MASTER_KEY` (consistent with KeyService), or
(b) leave it in `config.yml` (fdroidserver's standard practice, file chmod
    `0600`). Plan: do (a) — encrypt into DB, mirroring the existing pattern,
    and keep config.yml as the source of truth for fdroid itself.

## 2. Required container changes (new deployment must have a *writable* repo dir)

Current compose mounts the **output** dir read-only:

```yaml
volumes:
  - /srv/fdroid/repo/repo:/data/repo:ro     # only repo/ output, RO
```

`fdroid init` needs to write **config.yml + keystore.p12 at the repo root**
and **repo/** inside it. So the new deployment must mount the whole repo dir
**writable**:

```yaml
volumes:
  - /srv/fdroid/repo:/data/fdroidrepo        # full repo dir, RW (new deployment: empty)
```

With `RepoConfig.RepoPath` set to `/data/fdroidrepo/repo` (the output dir
inside the mounted tree). Serving stays `/fdroid/repo/*` → read-only from
`RepoPath`.

### 2.1 What a fresh host dir looks like before first boot

```
/srv/fdroid/repo/            ← host dir, EMPTY (or with backup)
  ├── config.yml          (absent → init will create)
  ├── keystore.p12        (absent → init will generate)
  ├── metadata/           (created by fdroid update -c)
  ├── repo/               (created by init; index here after update)
  ├── srclibs/  tmp/      (fdroidserver working dirs)
  └── build/  buildserver/ (optional)
```

## 3. API design: `POST /api/repo/init`

### 3.1 Flow

```
User (UI or curl)                        fdroidmgr container                 fdroidserver
──────────────────────────────────────────────────────────────────────────────────────────────
  POST /api/repo/init                    RepoInitService
  { repoName, repoDescription,
    keyAlias?, keystorePath? }           → 1. repo dir exists && config.yml present?
                                                yes → 409 RepoAlreadyInitialized
                                                no  → 2. run fdroid init --no-prompt ...
                                                │         --android-home /opt/android-sdk
                                                │         --keystore <abs path>
                                                │         --repo-keyalias <alias>
                                                │         (in cwd = /data/fdroidrepo)
                                                │
                                                │   fdroid init writes config.yml+keystore.p12 → exit 0
                                                │
                                          3. rewrite config.yml: repo_url, repo_name,
                                             repo_description (via python/yq or fdroid
                                             config keys — keep comments)
                                          4. run fdroid update -c  (create metadata)
                                          5. run fdroid update     (signed index)
                                          6. read generated keystorepass → AES-encrypt
                                             under FDROID_MASTER_KEY → store in DB
                                             (new column RepoKeystorePassEnc on RepoConfig)
                                          7. upsert RepoConfig row (RepoUrl, RepoName,
                                             RepoDescription, RepoPath=/data/fdroidrepo/repo)
                                     ← 201 { repoUrl, repoName, repoPath, keyAlias,
                                            pubkeyFingerprint, repoKeySha256 }
```

### 3.2 Endpoint contract

```http
POST /api/repo/init
Authorization: Bearer <jwt>
Content-Type: application/json

{
  "repoName": "My F-Droid Repository",
  "repoDescription": "Private repo on this machine",
  "keyAlias": "fdroid.example.com",         // optional; default = "fdroid-repo"
  "keystorePath": "/data/fdroidrepo/keystore.p12"  // optional
}
```

Responses:

| Code | Body |
|---|---|
| `201` | `{ repoUrl, repoName, repoPath, keyAlias, keystoreSha256?, pubkey }` |
| `409` | `{ error: "repo already initialized", repoPath }` — when config.yml exists |
| `400` | `{ error: "<field> is required" }` — missing repoName, or invalid provided URL |
| `502` | `{ error: "fdroid init failed", stderr }` — subprocess failure |

### 3.3 Where it runs: new `RepoInitService`

```csharp
public class RepoInitService
{
    // ctor: FdroidDb, ILogger, IConfiguration (for FDROID_MASTER_KEY, ANDROID_HOME)

    public async Task<RepoInitResult> InitAsync(RepoInitRequest req, CancellationToken ct)
    {
        // 1. guard: if config.yml exists → throw RepoAlreadyInitialized (→409)

        // 2. fdroid init --no-prompt
        //    WorkingDirectory = "/data/fdroidrepo"
        //    args: --android-home <ENV ANDROID_HOME> --keystore <abs> --repo-keyalias <alias>

        // 3. patch config.yml (repo_url / repo_name / repo_description)
        //    - simplest robust approach: pyyaml rewrite preserving comments is hard;
        //      instead append known keys or edit via python snippet:
        //        python3 -c 'import yaml,io; write repo_url/repo_name/repo_description'

        // 4. run `fdroid update -c` then `fdroid update`

        // 5. read keystorepass from config.yml → AES encrypt w/ master key → save

        // 6. upsert RepoConfig (RepoPath=/data/fdroidrepo/repo, RepoUrl, ...)

        // 7. return result (repoKeySha256 = fingerprint of repo signing key)
    }
}
```

Helper: `RunAsync(ProcessStartInfo)` — shared with `RepoIndexService`
(also fix **#bug**: `GenerateAsync` hardcodes `/srv/fdroid/repo`; it
must use the mounted repo root, e.g. derived from `cfg.RepoPath` parent or an
env `FDROID_REPO_ROOT=/data/fdroidrepo` — otherwise init and update run in
different directories).

### 3.4 RepoConfig DB changes

Add to `RepoConfig`:

```csharp
/// <summary>AES-encrypted keystore password for the repo signing key
/// (encrypted under FDROID_MASTER_KEY). Null until /api/repo/init runs.</summary>
public string? RepoKeystorePassEnc { get; set; }

/// <summary>SHA-256 fingerprint of the repo signing key (from keytool -list).</summary>
public string? RepoKeySha256 { get; set; }

/// <summary>Path of the most recent automatic backup of a pre-init repo
/// (set when POST /api/repo/init backed up an existing repo).</summary>
public string? BackupPath { get; set; }
```

(new migration / EnsureCreated handles it — project uses `EnsureCreatedAsync`,
so just add props + a safe ALTER for existing DBs)

### 3.5 Controller wiring

New endpoints on `RepoController`:

```csharp
[Authorize]
[HttpPost("init")]
public async Task<IActionResult> Init(RepoInitRequest req, CancellationToken ct)
// → 409 if config.yml exists; else RepoInitService.InitAsync

[Authorize]
[HttpGet("init/status")]
public async Task<IActionResult> InitStatus(CancellationToken ct)
// → { initialized: bool, repoPath, name? }  (config.yml exists? + RepoConfig row)
```

## 5. Backup of an existing working repo

Before (re-)initialization the manager must **never destroy** an existing
working repo. The current deployment has a live repo at
`/srv/fdroid/repo` (config.yml + keystore.p12 + signed index) that
clients already trust. Re-initializing in place would orphan those clients
(the repo signing key changes).

### 5.1 Backup behavior (on `POST /api/repo/init`)

- Detect an existing repo: `config.yml` (or `keystore.p12`) present in the repo root.
- If present → **copy the whole repo tree** to a timestamped backup dir
  *before* doing anything else:
  ```
  /srv/fdroid/repo         → /srv/fdroid/repo-backup-20260825T123456Z
  ```
- Backup uses a **copy** (not move) so the working repo stays in place until
  init succeeds; if init fails, the live repo is untouched.
- The backup path is returned in the API response and recorded in
  `RepoConfig.BackupPath`.
- If the target backup dir already exists, subsequent backups get a new
  timestamp suffix (`-2`, `-3`, …) — never overwrite an earlier backup.
- **Safety rule:** re-init is refused unless the caller explicitly passes
  `force: true`. With `force: true`: backup first, then init runs against a
  `repo` dir cleared *after* the copy succeeded.

### 5.2 What gets backed up

| Path (relative to repo root) | Why |
|---|---|
| `config.yml` | repo identity + sdk_path + keystorepass/keypass (plaintext) |
| `keystore.p12` | **repo signing key** — the client trust anchor |
| `repo/` | current index + published APKs |
| `metadata/` | app metadata used by fdroid update |
| `srclibs/`, `tmp/`, `build/` | fdroidserver state |

Backup is a plain recursive copy into a sibling backup root (e.g.
`repo-backup-<ts>` next to the repo root); no tar needed (host volume is
not compressed).

## 6. API tests (required behavior)

These are the acceptance tests the implementation must satisfy, from the
**API perspective** (HTTP surface, black-box).

### 6.1 Validation — what data must be passed

| Case | Request | Expected |
|---|---|---|
| (repo URL is not part of the request) | `{ repoName: "X" }` | `201` — URL derived from `FDROID_PUBLIC_URL` |
| missing `repoName` | `{ }` | `400` `{ error: "repoName is required" }` |
| invalid `keyAlias` (empty/space) | `{ repoName, keyAlias: " " }` | `400` `{ error: "keyAlias is invalid" }` |

### 6.2 Success — repo is created

| Case | Given | Expected |
|---|---|---|
| fresh (empty) repo dir | no config.yml, valid body | `201` + `{ repoUrl, repoName, repoPath, keyAlias, repoKeySha256 }`; `config.yml`, `keystore.p12`, `repo/` created on disk; `fdroid update` ran; `RepoConfig` row updated |
| init already done | config.yml exists | `409` `{ error: "repo already initialized", backupPath }` |
| force re-init | config.yml exists + `force: true` | `200`/`201` + backup created first; new keystore + index regenerated |

### 6.3 Failure — missing/validated data or subprocess errors

| Case | Given | Expected |
|---|---|---|
| unauthorized | no token | `401` |
| fdroid binary missing | runner simulates failure | `502` `{ error: "fdroid init failed", stderr }` |
| `fdroid update` fails after init | runner returns nonzero on update | `502` with message |
| backup dir not writable | repo root RO | `500` `{ error: "backup failed" }` — init must NOT run |

### 6.4 Additional behaviors to test

- `GET /api/repo/init/status` returns `{ initialized: bool, repoPath, name? }` —
  `false` on an empty dir, `true` when config.yml exists.
- `GET /api/repo/init/status` is accessible **without auth** (used by the UI
  wizard to decide what to show) — but `POST /api/repo/init` requires auth.
- Backup correctness: after backup, the original repo dir still serves valid
  files (config.yml + keystore.p12 present); backup dir contains the same set.
- Idempotency: calling `/api/repo/init` twice (without force) → 409 both times
  and only **one** backup dir created (no duplicate).
- RepoConfig row after init: `RepoUrl`, `RepoName`, `RepoDescription`,
  `RepoKeystorePassEnc` (non-null, decryptable with FDROID_MASTER_KEY),
  `RepoKeySha256` (64 hex).
- The keystore password never appears in API responses or logs.

## 7. Security & operational notes

- `fdroid init` writes `config.yml` and `keystore.p12` with **chmod 0600**
  (owner-only) — preserved through the volume (host dir owned by the runner
  user; ensure the container runs as a user that owns `/data/fdroidrepo`).
- Keystore password: do **not** log or return it in API responses. Store
  AES-encrypted under `FDROID_MASTER_KEY` (same key as app key passwords).
- `fdroid init` refuses existing repos — safe default; an explicit
  "force re-init" requires `force: true` + a successful backup first.
- The repo signing key is **the trust anchor** for clients. Losing
  `keystore.p12` + password = clients must re-add the repo. Backups are
  created automatically by the init flow before any destructive action.
- Container networking: `fdroid init` needs no network. `fdroid update`
  may fetch icons/descriptions for apps from the network if `repo_web_base_url`
  configured (out of scope here).
